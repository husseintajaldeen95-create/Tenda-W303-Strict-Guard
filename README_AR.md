# Tenda W303 Guard — النسخة التشخيصية الأولى

تطبيق Android مستقل بلغة Java، مستوحى من مشروع AX12 Strict Guard المرفق، وموجّه مبدئياً إلى واجهة Tenda W303R القديمة ذات Firmware `V5.07.46_en`.

## لماذا هذه نسخة تشخيصية؟

واجهة W303R من جيل قديم وتختلف جذرياً عن واجهة TP-Link/LuCI الموجودة في المشروع الأصلي. لذلك لم أنقل مسارات API أو رموز المصادقة الخاصة بـ TP-Link إلى Tenda. التطبيق الحالي يفتح واجهة الراوتر المحلية داخل WebView، ويتيح التنقل إلى صفحات DHCP وWireless وMAC Filter، وقراءة جداول MAC الظاهرة، وفحص أسماء الحقول والنماذج في الصفحة الحالية. لا ينفذ أي كتابة أو حظر تلقائي في هذه المرحلة.

هذا الاختيار مقصود: نحتاج أولاً إلى التقاط أسماء حقول HTML الفعلية في Firmware الجهاز قبل بناء عمليات تغيير الإعدادات. لا يجوز تخمين أسماء CGI أو حقول MAC أو أرقام السياسات.

## ما الذي يعمل في هذه النسخة؟

- فتح واجهة الراوتر محلياً (الافتراضي `192.168.0.1`).
- إدخال كلمة مرور الإدارة داخل صفحة Tenda نفسها؛ التطبيق لا يحفظها.
- اختصارات إلى DHCP Client List وWireless Connection Status وMAC Address Filter Settings وTime Settings.
- قراءة سجلات DHCP الظاهرة التي تحتوي على MAC، مع محاولة استخراج IP واسم المضيف ومدة الإيجار.
- فحص روابط الصفحة والنماذج وحقول الإدخال والقوائم المنسدلة وعناوين الجداول.
- نسخ تقرير التشخيص لإرساله كي نطابق الواجهة بدقة.
- حظر التنقل إلى أي عنوان خارج IP الراوتر المحدد.

## ما الذي لم يُفعّل بعد؟

- إضافة أو حذف MAC تلقائياً.
- تطبيق Allow List أو Block List آلياً.
- إنشاء جداول الإنترنت أو حفظها آلياً.
- خدمة مراقبة خلفية وإشعارات دخول/خروج الأجهزة.

لن تُفعّل هذه الوظائف إلا بعد الحصول على تقرير النماذج من صفحة MAC Address Filter وقراءة صفحة DHCP/Connection Status على الجهاز الفعلي، ثم اختبار الحفظ على قاعدة واحدة غير حرجة والتحقق بإعادة القراءة.

## ما يدعمه دليل W303R

دليل Tenda 11N Wireless Broadband Router يصف ما يلي:

- `DHCP Client List`: يعرض Host Name وIP Address وMAC Address وLease Time.
- `Wireless > Connection Status`: يعرض MAC للأجهزة اللاسلكية المتصلة وعرض القناة.
- `Security > MAC Address Filter`: يدعم `Permit only` و`Forbid only` ورقم سياسة وRemark وعنوان MAC ووقتاً وأياماً وخيار Enable.
- `0:00–0:00` في قاعدة MAC Filter موصوفة كقاعدة تعمل 24 ساعة يومياً؛ لذلك لا ينبغي تفسيرها على أنها مدة صفرية.

مرجع الدليل: https://tenda.cz/sites/Upload/W303R/W303R_UG.pdf

## إعداد الفترة 16:00–24:00

لمنع جهاز خارج هذه الفترة فقط، فإن الخطة المرشحة حسب منطق `Forbid only` هي قاعدة منع لذلك الجهاز من `00:00` إلى `16:00` مع اختيار الأيام المطلوبة. يلزم تأكيد السلوك الفعلي على الراوتر قبل تعميم القاعدة على أجهزة متعددة. يجب أيضاً التأكد من ضبط ساعة الراوتر من `System tools > Time Settings`.

**تنبيه:** `Wireless Access Control` يتحكم في السماح بالاتصال اللاسلكي، أما `Security > MAC Address Filter` فهو الخيار الذي يصفه الدليل للتحكم في وصول أجهزة LAN إلى الإنترنت حسب الوقت. لا تخلط بين الوظيفتين.

## الأمان

- يجب تشغيل التطبيق والهاتف على شبكة الراوتر المحلية.
- التطبيق لا يرسل بيانات إلى خادم خارجي.
- كلمة المرور لا تحفظ في التطبيق؛ أدخلها فقط في صفحة إدارة الراوتر المحلية.
- التطبيق يرفض التنقل إلى عناوين خارج IP الراوتر المحدد.
- لا تستخدم الإدارة عن بُعد من الإنترنت لهذا التطبيق.
- لا تعتمد على MAC وحده كحماية مطلقة؛ يمكن لبعض الأجهزة استخدام MAC عشوائي أو تغييره.

## بناء APK عبر GitHub Actions

1. أنشئ مستودع GitHub جديداً.
2. ارفع محتويات هذا المجلد مباشرة إلى جذر المستودع (بحيث يظهر `settings.gradle` في الجذر).
3. افتح تبويب Actions وشغّل `Build Tenda W303 Guard APK` أو ادفع commit جديداً.
4. نزّل ملف APK من Artifacts في تشغيل Workflow.

إعدادات البناء: Android Gradle Plugin 8.6.1، Gradle 8.7، JDK 17، Android SDK 35.

## المطلوب للمرحلة التالية

بعد تثبيت التطبيق وفتح صفحة `Security > MAC Address Filter Settings`:

1. اضغط `فحص حقول الصفحة الحالية`.
2. اضغط `نسخ تقرير التشخيص`.
3. أرسل التقرير هنا بعد التأكد من عدم احتوائه على كلمة مرور أو Cookie أو بيانات حساسة.

ثم افتح `DHCP Client List` وكرر التشخيص. هذه المعلومات ستسمح ببناء عمليات قراءة/كتابة مخصصة للـ Firmware الفعلي بدلاً من التخمين.
